# 05 测试计划

## 自动化测试

- mock reader 默认 `empty` 场景输出无人、无跌倒的 `RadarFrame`。
- `fall-demo` 场景包含跌倒阶段，`presence-demo` 场景包含无人和有人阶段。
- 持续跌倒达到阈值才确认，短暂信号不会直接报警。
- 官方状态报文可解析，损坏帧可重新同步，任意分块和不完整 bytes 不崩溃。
- replay 对小 chunk 的 `.bin` 可正常回放。
- WebSocket JSON 可序列化全部关键状态并校验设备事件。
- 取消确认报警后，同一连续跌倒不会重新报警。

## 真实场景采集

按顺序分别采集，并为每份 `.bin` 保存 metadata：

1. `empty`：检测区无人。
2. `standing`：正常站立。
3. `walking`：不同方向和速度走动。
4. `sitting`：正常坐下并保持。
5. `lying`：缓慢主动躺下，用于误报测试。
6. `fall`：在软垫与保护人员协助下模拟跌倒并静止。
7. `recovery`：跌倒状态后起身。

每次记录安装高度、角度、人与雷达距离、动作时间、参与保护人员、parser 输出、状态机输出和是否报警。床、被子、椅子、风扇和多人活动可作为干扰场景。

## 端到端验收

- LD6002C 串口连续读取无异常。
- Python frame CSV 与 event CSV 字段正确。
- Dashboard 能显示最新状态、最近帧和最近事件。
- StickS3 断线可重连，六种状态显示正确。
- 疑似状态只短鸣一次，确认状态循环报警。
- Button A 本地立即静音，Python 收到并记录取消，旧事件不重报。
- 重启 Python、断开 Wi-Fi、重插两套 USB 后可以恢复。
